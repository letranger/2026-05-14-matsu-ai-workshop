# 小論文初稿生成器（主流程＋兩種延伸）

把「依研究筆記、圖表、論文格式寫一篇高中生科學小論文」這條重複性的流程，
寫成一份 SOP（Standard Operating Procedure）打包進這個 Skill。

下一次要寫新主題的小論文，使用者只要說一句：

> 「小論文流程，幫我依研究題目、研究素材、圖、論文格式寫一篇小論文初稿。」

本 Skill 就會自動接管後續流程，不必每次解釋一遍要怎麼做。

---

## 主流程：從研究筆記到小論文 docx

### 步驟 1：確認輸入

跟使用者要齊以下四項，缺哪項就逐一詢問：

| 項目         | 要求                                                          |
|--------------|---------------------------------------------------------------|
| 論文主題     | 一句話。例如：「馬祖藍眼淚的成因之爭——自然現象抑或環境警訊？」|
| 研究筆記     | 一份 `.docx` 或 `.md`，內含論文章節素材、引註編號、參考文獻   |
| 圖 1（PNG）   | 通常是「成因因果關係圖」之類，將嵌入「研究結果」段             |
| 圖 2（PNG）   | 通常是「歷史／時間軸」，將嵌入「研究結果」段                   |

### 步驟 2：讀取格式範本

使用本 Skill 資料夾內附的 `小論文範本.docx`——這是「全國高級中學小論文寫作比賽」
官方版本（台北市開南高商發布）。格式規範如下：

- 字型：新細明體 12 級；英文 Times New Roman 12 級
- 紙張：A4、邊界 2 cm × 4、單行間距
- 標題單獨成行，標題／段落間空一行，靠左對齊（不退兩格）
- 頁首加篇名、頁尾加頁碼（10 級置中）
- 引註：原文加粗加『』，引用結束標「（作者，年代）」
- 圖編號／標題在「下方」置中；表編號／標題在「上方」

### 步驟 3：依下列章節順序產出

| 章節                          | 字數         | 說明                                                |
|-------------------------------|--------------|-----------------------------------------------------|
| 封面頁                        | —            | 篇名／作者（姓名。學校。部別/年級）／指導教師／日期 |
| 壹、前言                      | 200–500 字   | 研究動機與研究目的                                  |
| 貳、正文                      | 1,200–3,000 字 | 含文獻探討、研究方法、研究結果、討論                |
|   一、文獻探討                | —            | 依研究筆記分段、每段含引註                          |
|   二、研究方法                | —            | 說明本研究的方法、資料來源、分析步驟                |
|   三、研究結果（嵌圖）        | —            | 「（一）成因因果分析」嵌圖 1；「（二）時間軸觀察」嵌圖 2 |
|   四、討論                    | —            | 回答「研究結果代表什麼意思」                        |
| 參、結論                      | 200–500 字   | 研究發現、研究限制、後續研究建議                    |
| 肆、引註資料                  | —            | 沿用研究筆記中的編號與來源，每筆含 URL／DOI         |

### 步驟 4：內容紀律

- *只能用研究筆記裡的事實*——不新增論文沒提的科學主張或數據
- *引註必須沿用研究筆記中的編號與來源*——保持可追溯性
- 段落層次用「一、（一）、1、（1）」四層為原則

### 步驟 5：輸出

- 一份 `.docx` 檔案
- 排版盡量貼近 `小論文範本.docx`
- 篇幅總計 1,600–4,000 字（不含參考資料）

## 延伸 A：換骨架（同一份內容換成別的格式）

當使用者完成論文後說「幫我換成研習心得／行政報告／教案／科展」，
請查閱本資料夾內 `換骨架-prompts.md` 對應的變體 prompt，依該變體執行。

四個變體：

| 變體 | 用途         | 主要結構                                |
|------|--------------|-----------------------------------------|
| A    | 研習心得     | 800 字、第一人稱、含反思                |
| B    | 行政報告     | 主旨／緣由／辦理情形／建議事項／預算    |
| C    | 跨域教案     | 學習目標／教學流程／評量規準            |
| D    | 科展報告     | 研究動機／方法／結果／討論              |

執行時的紀律與主流程一致：*不新增論文沒提的事實、引註沿用、輸出 .docx*。

## 延伸 B：生成投影片（reveal.js HTML 簡報）

當使用者完成論文後說「幫我做投影片」「生簡報」「reveal.js 版」，
依下列規格產出一份 *單檔 HTML 投影片* （inline CSS／JS，瀏覽器直接開）。

### 投影片結構（10 張內）

| 第 N 張 | 內容                                                   |
|---------|--------------------------------------------------------|
| 1       | 封面：題名、作者、日期                                 |
| 2       | 研究動機（前言節錄、3-5 個 bullet）                    |
| 3-4     | 文獻探討重點（兩派觀點對照、引註簡標）                 |
| 5       | 研究方法（文獻分析法、資料來源、分析步驟）             |
| 6-7     | 研究發現——嵌入圖 1（成因因果）、圖 2（時間軸）        |
| 8       | 討論：研究結果代表什麼意思？                           |
| 9       | 結論：發現＋限制＋後續研究建議                         |
| 10      | Q&A 收尾                                                |

### 視覺規格

- *深色背景* （深藍 #0f1b3d 或近黑），白字
- 字型：~PingFang TC~ / ~Microsoft JhengHei~ / sans-serif
- 標題級用大字（h1 ≈ 48px、h2 ≈ 32px）
- 內文 24px，bullet 一張 5 點以內
- *學術簡潔風* ：不要花俏動畫、不要漸層、不要 emoji
- 圖片嵌入時 ~max-height: 70vh~ 避免溢出

### 技術規格

- *單檔 HTML* ：inline CSS、inline JS，不引用外部資源（圖片以 base64 內嵌或 user 自行調整）
- reveal.js 用 [[https://cdn.jsdelivr.net/npm/reveal.js@4/dist/][CDN 版]]，linked from inline `<script>` 標籤
- 鍵盤左右鍵切換投影片、Esc 看 overview
- 列印模式：~?print-pdf~ 加在網址後可直接列印成 PDF

### 內容紀律（重要）

- *投影片內容必須與論文一致* ——不從論文找不到的內容
- *引註保留* ：每個論點末標 ~(註一)~ 等
- *圖片用論文裡的兩張* ——不要重新生成圖

### 觸發後操作

1. 先問使用者：「您希望同時保留論文 docx 嗎？還是只要簡報？」
2. 若使用者只要簡報，直接從研究筆記 + 兩張圖產出簡報，跳過 docx
3. 若使用者已有完整論文，直接從論文摘要產出簡報

### 輸出

- 一份 `slides.html`，可在瀏覽器直接開啟瀏覽
- 配發給使用者「列印 PDF」或「截圖」的指引（若使用者問如何轉檔）

## 注意事項

1. *本 Skill 不會替使用者做「Step 1 蒐集素材」（NotebookLM）和「Step 2 畫圖」
   （Napkin）* 這兩步在 Skill 外部完成；本 Skill 假設使用者已備齊研究筆記與圖。

2. 若使用者只給了主題、沒給研究筆記，請說明：
   > 「請先用 NotebookLM 整理研究筆記、用 Napkin 畫兩張圖，
   > 然後一併上傳給我。我會接手寫論文（與可選的簡報）。」

3. 若研究筆記缺少引註編號，請提示使用者補上——*否則無法做引註可追溯的論文*。

4. *不要呼叫網路搜尋* 或新增外部來源——本 Skill 的目的是「依使用者上傳的素材
   組合論文與簡報」，不是「找新資料」。

5. *延伸 A、B 是「可選」* ——使用者完成主流程後若沒主動要，不必詢問。
   若主動要，再依規範執行。
